# PR #54 — Fixes for code review

This plan resolves the open items flagged in PR #54's code-review
pass. Each item is its own commit so the diff against the PR is
easier to review.

## Critical (must fix before merge)

1. **Fidelity tests fail with `project: empty reference`** — the
   `drive`/`driveRaw` helpers in `tests/fidelity/fidelity_test.go`
   don't thread the project field. Fix by passing the repo root
   through the helper signature and applying `driveWithProject`
   inside the helper.

2. **`repofixture.ProjectURI()` not added** — the plan called for a
   `ProjectURI string` field on `Fixture`; instead three helpers
   (`seedRegFromRepo`, `seedRegForRoot`, `withProject`) are scattered
   across `internal/tool/helpers_test.go`. Add `ProjectURI()`,
   `Registry()` and the matching helpers to `repofixture` and delete
   the scattered copies.

3. **`ParseRef` percent-encoded traversal blind spot** — `url.Parse`
   already decodes `u.Path`, so most percent-encoded traversal slips
   through the guard today. Add belt-and-suspenders: call
   `url.PathUnescape` explicitly on the raw path and re-check the
   traversal patterns. Add tests for double-encoded (`%252e%252e`)
   cases that demonstrate what *does* pass through (literal `%2e%2e`
   in a filename, which the OS treats as data, not `..`).

4. **`index_repository` unconditionally reloads** — `store.Load`
   runs on every invocation. Short-circuit when the registry entry
   already exists and the disk cache is fresh, returning the
   existing entry with `reloaded:false`. Audit/TOFU emit remain
   memoised by `sync.Once` (unchanged).

## Important

5. **`mcp serve --help` doesn't mention `file://` URIs** — update
   the usage string to show the wire shape explicitly.

6. **`treeoverview` deprecation shim** — `"file://" + a.Repo`
   breaks when `a.Repo` already starts with `file://`. Detect an
   already-URI shape and pass through; only wrap raw paths.

7. **`mcp_dispatch_test.go` may not exercise real JSON-RPC** —
   verify by inspection. It pipes real JSON-RPC requests to the
   server's stdio and reads responses on the stdout side; that IS
   the JSON-RPC framing path, not a function-call round-trip.
   No code change; add a code comment so the next reviewer sees it.

## Minor

8. **CHANGELOG deprecation window lacks version pin** — pin to the
   next minor (`0.2.0`) so users know when `repo` is removed.

9. **Hard-coded MCP protocol version** — extract `"2024-11-05"` to
   a const in `internal/mcp` so it lives next to the comment that
   already explains the choice.
